# VitalQuest Visual Brand Bible

## Brand idea
**VitalQuest turns real effort into visible growth.**

VitalQuest should feel like a premium performance platform with the emotional payoff of a progression game. It is not a fantasy dashboard and it is not a conventional fitness tracker with game colors layered on top.

The visual hierarchy is:
1. **Performance clarity** — the user immediately understands what matters and what to do.
2. **Progression identity** — XP, levels, attributes, Arcs, milestones, rewards, and forms make effort feel cumulative.
3. **Optional fantasy expression** — archetypes and skins change atmosphere and representation without changing product comprehension.

## Brand personality
VitalQuest is:
- cinematic, not theatrical
- premium, not ornate
- disciplined, not sterile
- intelligent, not clinical
- aspirational, not motivational-poster loud
- game-informed, not game-dependent
- dark, luminous, dimensional

The emotional target is **controlled intensity**.

## Core brand motif: the Arc
The Arc is the primary visual metaphor across the product.

It can appear as:
- eclipse rims
- partial circular progress tracks
- horizon curves
- thin orbital lines
- radial calibration marks
- subtle rings behind major milestones
- motion paths for progress and loading

Avoid using the Arc as decoration on every card. It should signal **progress, calibration, transition, or milestone**.

## Eclipse language
The eclipse is the flagship brand image because it expresses:
- potential becoming visible
- progress emerging from disciplined repetition
- light at the edge rather than instant transformation

Use eclipse artwork for:
- launch / loading
- major progression milestones
- Arc transitions
- select campaign / marketing moments

Do not make every primary screen a literal eclipse scene.

## Color system
### Core shell
- Obsidian: `#080A0A`
- Graphite: `#1A1D24`
- Slate: `#2C323D`
- Steel: `#4B5563`
- Ivory: `#F7F8FA`

### Functional states
- Positive / complete: restrained luminous green from current theme system
- Warning / fatigue: restrained amber
- Error: restrained red, never neon
- Muted text should remain high enough contrast for accessibility

### Accent behavior
The shell should remain neutral. Accent color is earned through hierarchy:
- primary action
- current state
- progress
- next milestone
- selected archetype

Do not flood entire surfaces with accent color.

## Typography
The product should use two voices:

### Display voice
Use an elegant, high-contrast serif or similarly premium editorial face for:
- major page titles
- level-up moments
- Arc completion
- milestone ceremony
- key numeric achievements when appropriate

The display voice creates gravitas.

### System / performance voice
Use a clean modern sans-serif for:
- navigation
- labels
- metrics
- coaching explanations
- workout controls
- tables and charts

The system voice creates speed and clarity.

### Type hierarchy
1. Display headline — emotional / ceremonial
2. Section title — strong functional hierarchy
3. Primary metric — large and immediate
4. Body / coaching copy — readable, compact
5. Eyebrow / metadata — uppercase, wide tracking, sparingly used

Avoid microtype so small that the interface only looks polished in screenshots. Mobile readability wins.

## Materials
The app should feel built from premium layered materials rather than generic cards.

### Base surfaces
- near-black matte background
- graphite elevated planes
- subtle tonal separation instead of heavy borders

### Elevated modules
Use combinations of:
- soft internal highlights
- thin luminous edge lines
- low-opacity gradients
- faint noise / texture where performance permits
- restrained depth shadows
- small radius differences to imply hierarchy

### Hero / progression surfaces
May introduce:
- metallic edge treatment
- glass / smoked glass
- illuminated Arc lines
- radial light
- subtle environmental artwork

Avoid:
- thick neon outlines
- gradients on every card
- decorative chrome everywhere
- primitive CSS fantasy shapes

## Navigation
Primary navigation remains:
**Today · Training · Goals · Rewards · Progress**

Navigation should feel like part of the product chassis.

Mobile:
- persistent bottom navigation
- strong selected state
- generous tap targets
- no floating visual noise

Tablet:
- retain the same order and icon language
- stronger spatial presence
- never stretch controls awkwardly across landscape

## Icon language
Icons should be:
- geometric
- dimensional enough to feel premium
- legible at 20–28px
- consistent in stroke / mass

Avoid emoji and mixed illustration styles.

Archetype-specific icons may be introduced only in progression/reward contexts.

## Motion
Motion communicates system intelligence and progress.

### Standard motion
- 180–300ms
- soft ease / restrained spring
- small vertical or scale movement
- never bounce-heavy

### Primary interaction
- subtle press compression
- immediate visual acknowledgement

### Progression motion
Can be more ceremonial:
- Arc sweep
- radial glow
- progress line fill
- attribute count-up
- reward reveal
- level transition

### Loading
- launch: branded eclipse image + restrained pulse
- intelligence work: branded calibration image + status copy
- local saves: compact inline progress, never a full takeover unless the user cannot continue

## Information density
VitalQuest is deep, but it should not feel dense.

Rules:
- one dominant action per screen section
- advanced intelligence is progressive disclosure
- Today is a decision screen, not a dashboard archive
- Training can be deeper but must preserve a clear top-to-bottom narrative
- Goals, Rewards, and Progress should not repeat Today

## Primary screen jobs
### Today
Answer within seconds:
1. How am I doing?
2. What should I do today?
3. Why?

### Training
Explain and manage:
- recommendation
- readiness
- Arc
- 7-day plan
- objective
- alternatives
- tools/library

### Goals
Show:
- active goals
- progress
- completed milestones

### Rewards
Show:
- what is earned
- what is close
- what is locked and why

### Progress
Tell the long-term story:
- level
- attributes
- form
- lifetime history
- archetype representation

## Artwork rules
Artwork should be high-quality generated or purpose-made imagery.

Use artwork for:
- hero moments
- loading
- progression milestones
- reward reveals
- archetype identity

Do not use artwork to replace functional UI clarity.

Never recreate premium artwork with primitive CSS shapes, emoji, simplistic SVG scenes, or color-only theme swaps.

## Skin architecture
The underlying information architecture is identical across skins.

A skin may change:
- environmental artwork
- surface material
- accent lighting
- hero representation
- progression iconography
- framing details
- ceremonial motion

A skin may not change:
- navigation position
- information meaning
- core control behavior
- accessibility
- metric semantics

## North Star standard
Every primary screen should pass these tests:
- understandable in 3–5 seconds
- strong single visual hierarchy
- useful without artwork
- elevated by artwork rather than dependent on it
- readable on iPhone
- intentional on iPad landscape
- unmistakably VitalQuest when screenshots are shown without the app name

## Design sequence
1. Lock functional state and responsive behavior
2. Apply this brand system to Today as the North Star
3. Propagate the same system to Training
4. Propagate to Goals, Rewards, Progress
5. Build skin-specific visual layers
6. Add final progression ceremony and motion polish
